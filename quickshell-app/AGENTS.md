# Omarchy search plugin

Read `README.md` in this directory and the repository's root guidance first.

- This is the EmbeddingGemma 2 multimodal-search plugin for Omarchy Shell. Keep inference native, with the QML panel hosted in the existing shell.
- Keep native ML/decoding and catalog code in `crates/fractal-search-core/`; UI orchestration and the service transport belong in `quickshell-app/`.
- Keep summon, results and settings as states of one launcher panel. The initial visible panel and mouse input region must fit the search bar and its always-visible hotkeys footer. Animate the painted panel inside a fixed transparent native surface large enough for results/settings; keep that surface unchanged across page transitions to avoid competing compositor geometry animations. Keep input and compositor-visible regions aligned with the painted bounds, and avoid per-frame native window resizing. Use a Hyprland popup focus grab with on-demand layer focus, releasing it for native pickers/external apps; outside clicks dismiss the panel. Preserve keyboard selection, inline preview, visible errors and native folder pickers. Use the bundled desktop-portal helper for native selection; never instantiate QtQuick.Dialogs FolderDialog inside the shared host, since the GTK/GVfs implementation can abort the shell. Cancellation must close the portal request and errors must remain visible. Escape/close-after-open dismisses the resident panel; Ctrl+Q and the plugin quit call drain and stop only the backend. Native window close hides the plugin. Never call Qt.quit in an installed plugin.
- Use Qt Quick/QML and the installed Quickshell API. Size the panel through layer-shell instead of desktop window rules. Release keyboard focus and lower the panel for native pickers and successful external open/reveal requests; restore focus when summoned or a picker closes. Ctrl+Q and the settings Stop service button require the shared confirmation with Cancel focused by default; the explicit plugin quit method remains immediate for service lifecycle/tooling. Optional `--bind-close` installation owns a marked Super+W block, preserving normal closing outside the focused panel/picker and removing the block on uninstall. Never close an unrelated application after IPC failure. Edit desktop configuration only when the user explicitly requests it; follow the Omarchy skill and preserve existing bindings.
- Keep Settings organized as Folders, Preferences and Performance, with fixed tabs above scrolling content. Keep folder watching (Keep folders up to date) under Folders. Use `ResultActions.qml` for visible Open file / Show in folder controls in preview and narrow/list-only layouts. Use `SearchConfirmationDialog.qml` for folder removal and Ctrl+Q/Stop service with Cancel focused by default. Do not add a Browse all photos action; the current UI offers list-and-preview and list-only layouts. Keep technical setup/diagnostics under Performance and avoid hover tooltips on folder removal.
- Use Omarchy’s shared Color/Style theme and font/spacing tokens. Backend failures must be visible. Secondary text needs sufficient contrast even if the theme's `muted` color is dark.
- The same-user private Unix socket / worker NDJSON service is a trusted desktop transport that can index selected folders and open originals. It is not an MCP server and must never be advertised as a privacy-safe agent interface.
- `fractal-search-mcp` is a separate read-only stdio server using `fractal-search-core::agent`. It must not create/migrate the catalog, repair caches, read originals or expose original path metadata/file bytes. Bounded cached text excerpts are permitted; nonvisual thumbnail handles are null. Metadata tools never load models; semantic search lazily starts only the text model. Keep request/response/concurrency limits, strict schemas, safe opaque handles and thumbnail reencoding intact. stdout is JSON-RPC only. See `MCP.md`.
- CUDA is an explicit opt-in feature/provider. Keep CPU builds usable without NVIDIA libraries, reject unsupported provider selections and never retry failed CUDA model initialization/inference on CPU. CUDA bundles carry the ONNX provider libraries; selected NVIDIA runtime libraries must be loader-visible to the service, diagnostics and MCP wrapper. Diagnostics run without opening the catalog or loading models and distinguish missing dependencies from unverified inference. CPU and CUDA must use the same pinned FP32 precision/profile.
- Bound frames, requests, pages, decoded images, and results. Reject unknown fields and incompatible model assets/profiles; no silent provider or decoder fallbacks.
- Indexing must report source-file read/decode/change errors individually and continue healthy files, preserving any previous entry for the failed path. Model, traversal, database and cache-write failures remain fatal. Keep per-file progress errors and the bounded final failure report visible in the UI.
- Completed banners may be explicitly acknowledged, but retain the skipped-file report in Settings until the next scan and reannounce new failures. Parent item popups to the persistent canvas, not a native overlay that is destroyed on hide. Close visible popups before hiding the panel and restore search focus after closing them. Wait for a correctly sized submitted native buffer before presenting a newly mapped card or starting its resize animation; include actual mouse interactions and compositor captures in UI validation.
- Runtime catalogs, model caches, previews and thumbnails stay outside the repository. Tests must use temporary catalogs and synthetic media, never the user's library.
- The backend owns one resident model worker. Cancellation/close stops admission, finishes in-flight inference and saves completed files before releasing models and exiting. Incomplete multi-segment files retain their previous complete rows. UI reload or hide must not own/terminate this worker. A systemd user daemon owns it; UI reconnection restores active work/report state. Explicit service stop waits for that exit.
- Run root workspace formatting/check/tests, real-inference smoke checks when pinned assets are available, and UI empty/error/loading/populated/preview/shutdown checks. Use `FRACTAL_SEARCH_UI_TEST=1` only for test IPC; leave it unset in production. Run simulated keyboard/mouse input only in an isolated compositor, never the user's shared desktop session. Shared-session validation must use read-only inspection, scoped plugin IPC, or physical input from the user. Cleanup must not send input after hiding a test surface.
- Model/profile changes require a new catalog profile and explicit reindexing. EmbeddingGemma 2 is a clean replacement with no legacy-model compatibility. Preserve the native 768-dimensional FP32 `sentence_embedding` graph, project the leading 512 values and L2-normalize every indexed/query vector. Keep explicit full-768 native parity tools separate; no user dimension selector. Preserve the search-query task prefix, the 8,192-token model context and the app's 4,096 UTF-8-byte query bound. Images use 16-pixel patches, pooling kernel 3 and a fixed 280-soft-token budget with 2,520 padded patch slots. Index images, UTF-8 `.txt`/`.md`/`.markdown` passages (max 2 MiB/file, 4,096 bytes/passage), audio and video in the shared normalized 512D indexed space. Keep schema 4 with indexed profile `embeddinggemma2-daa72c51-fp32-multimodal-mrl512-v2`; reject the previous 768D profile clearly. Require a separate fresh catalog and explicit reindexing, leaving old catalogs untouched. The native asset manifest stays unchanged. Audio uses mono 16 kHz segments up to 30 seconds; video uses 1 fps visual segments up to 30 frames/30 seconds at 140 soft tokens/frame, with available soundtracks indexed as separate audio segments. Require ffmpeg/ffprobe explicitly and cap audio/video at 2 GiB/two hours. Do not imply PDF/Office indexing, transcription or timestamp-aware playback. `assetCount` counts segments and `fileCount` counts distinct files. Display type/time/excerpts and use no image preview requests for text/audio; video uses cached thumbnails.

- `manifest.json` declares `fractal.search`, its panel entry and keepLoaded behavior. Install UI and prebuilt backend together through `packaging/install.sh`; Omarchy’s git plugin installer does not run backend hooks. Package with `scripts/package-fractal-search.sh`; include no models/generated files in source control. Preserve existing catalog/cache on update/uninstall, validate checksum/architecture/runtime requirements and fail explicitly on setup errors.
- `ui/shell.qml` is an isolated developer harness, excluded from product bundles. Only this harness may own a ShellRoot/Qt.quit; the plugin runs inside the existing Omarchy process.
- First-run model setup uses the runtime’s pinned manifest, HTTPS-only downloads, progress and size/SHA verification. Existing verified files are reused; incomplete files cannot be loaded.
- The installed unit uses `--warm-search` to prepare text search in the background on startup without loading vision/audio or downloading assets. Keep the compact panel usable while startup proceeds, retain typed queries, and surface warmup failures across reconnects. “Prepare search at login” uses the actual systemd enabled state rather than a duplicated catalog preference; toggling it changes future graphical-session startup without stopping current work. Preserve registration across updates and disable it on uninstall.

- Accelerator status must distinguish configured, available and active providers. Grey out GPU when requirements fail; do not label a disconnected CUDA service as active CPU. Keep diagnostics collapsed by default, errors visible, and the full report copyable for sharing with an agent. Automatic preflight must not load models or switch providers.

- Keep the explicit All file types / Images / Text / Audio / Video filter paired with query and folder scope. Only Text query searches use BM25 + semantic RRF; empty-query browsing remains model-free. Label the optional hybrid score separately; never present it as a percent or re-sort by cosine. Invalidate stale result/progress/error/preview responses immediately on query/type/folder changes and across warmup/reconnect, with bounded latest-intent coalescing. Keep strict optional `mediaKind` request schemas and read-only MCP projections free of full internal lexical passages. See [hybrid contract](../docs/HYBRID-TEXT-SEARCH.md).
