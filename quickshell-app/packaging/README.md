# Fractal Search for Omarchy

This bundle installs the `fractal.search` panel in the existing Omarchy Shell and its native Rust backend as a systemd user service. No Rust compiler, Python environment or separate Quickshell instance is required.

Run `./install.sh`, then `omarchy-shell shell toggle fractal.search`. Bind that command to your preferred shortcut. Use `./install.sh --bind-close` to integrate Super+W: the focused Fractal panel hides, its focused folder picker cancels, and other application windows retain normal closing. The installer backs up personal bindings, refuses to replace a personal Super+W override, and validates Hyprland's configuration. Updates retain this managed binding; uninstall restores the default by removing only its managed block. On first open, choose **Set up model** (~2.96 GB); previously downloaded files are verified and reused. **Choose folder** in Settings can select an existing pinned EmbeddingGemma 2 model folder instead.

Omarchy/Quickshell, curl, jq, libheif, libjpeg-turbo and gcc-libs are runtime requirements, along with xdg-desktop-portal and a FileChooser backend (xdg-desktop-portal-gtk on Omarchy). The installer checks dependencies and reports missing packages with Omarchy installation instructions.

Esc goes back within settings/results, then hides the panel. Super+W closes the whole panel when the close binding is installed; indexing and folder watching continue. Ctrl+Q and Settings → Stop service ask for confirmation, with Cancel focused by default. Confirming finishes active work, checkpoints the catalog and stops only the backend. Summoning starts it again. Omarchy UI reloads reconnect to active indexing and its skipped-file report. Disable/remove the panel with Omarchy to hide it; run `systemctl --user stop fractal-search.service` to stop background work, or use the bundled `uninstall.sh` for complete removal. Catalog/models are retained by uninstall. Close-routing IPC errors are reported as desktop notifications and never close the application behind an unresponsive panel.

Data: `${XDG_DATA_HOME:-~/.local/share}/fractal-search`. Models: `${XDG_CACHE_HOME:-~/.cache}/fractal-search/models/embeddinggemma2-daa72c51`. Logs: `journalctl --user -u fractal-search.service`. The service starts on demand and is not enabled at login by the installer. Close the earlier standalone prototype with Ctrl+Q before installing; the catalog lock rejects simultaneous workers.

Updates: run the new bundle's installer. It drains the old service before replacing the UI/runtime. Models and catalog remain in place. `SHA256SUMS` detects incomplete or damaged bundles; it is not a release signature.

After a successful install, obsolete runtime builds are removed automatically. The current and immediately previous builds are retained, including across reinstalls; builds still running or containing the configured CUDA library directory are retained until a later update. Failed installs do not prune builds. Cleanup is limited to recognized runtime bundle directories and preserves catalogs, models, shared CUDA libraries and unrelated files. Cleanup errors are reported without rolling back the successful installation.

Opening Fractal starts a stopped service and prepares the text-search model in the background. **Settings → Load search model at login** starts that preparation at graphical login instead, before you open the panel. It is off by default, persists across updates and is disabled on uninstall. Changing the option does not stop the current service. The vision model remains lazy, and startup does not download models. The unit drains on graphical logout; the desktop shell is never stopped.

Native folder selection uses the bundled portal helper and the system’s separate picker process. GTK picker code is not loaded into Omarchy’s shared shell. Cancellation closes the portal request; missing portal support and helper errors are reported visibly.

CUDA-capable bundles support `./install.sh --provider cuda --device-id 0`, with optional `--cuda-lib-dir /absolute/path/to/libraries`. Install a compatible NVIDIA driver, CUDA 12 runtime libraries and cuDNN 9 first. A CUDA compiler is unnecessary. Settings → CUDA accelerator diagnostics lists missing libraries and loader errors even when model startup fails; Refresh and Copy details help troubleshoot. The preflight does not claim successful inference. Missing dependencies fail visibly and never switch model inference silently to CPU. Provider/device/library configuration persists across updates; use a CUDA bundle for updates, or explicitly pass `--provider cpu` to change providers.

The stable read-only MCP command is `$XDG_CONFIG_HOME/omarchy/plugins/fractal.search/fractal-search-mcp` (normally under `~/.config`). It uses the same independent Quickshell catalog and may run alongside the panel; see `MCP.md` for client configuration, tools, limits and privacy guarantees. No original paths or original image bytes are exposed. Metadata calls require no models; semantic search loads only the text model. MCP defaults to CPU unless its client arguments explicitly select CUDA.

EmbeddingGemma 2 and schema 4 require a fresh catalog and explicit reindexing. Installation never deletes or converts older data. Select the cache root containing tokenizer.json and onnx/ when choosing an existing model folder. FFmpeg and ffprobe are required for audio/video indexing.
